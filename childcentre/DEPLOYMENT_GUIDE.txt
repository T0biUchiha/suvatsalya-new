SUVATSALYA RELEASE CHECKLIST
============================

Live website: https://suvatsalya.in

This is intentionally provider-neutral. Configure the existing hosting environment;
do not treat this file as instructions to migrate the site to a different service.

BEFORE RELEASE
--------------

1. Frontend checks

   cd client
   npm ci
   npm run format:check
   npm run lint
   npm run build

2. Backend checks

   cd suvatsalya-backend
   npm ci
   node --check server.js

3. Confirm private backend environment variables are present:

   MONGO_URI
   JWT_SECRET
   CLOUDINARY_CLOUD_NAME
   CLOUDINARY_API_KEY
   CLOUDINARY_API_SECRET
   PORT
   CORS_ORIGIN
   ADMIN_RESET_SECRET

4. Confirm the production frontend has its API base URL configured through its
   private deployment environment.

RELEASE SCOPE
-------------

- Frontend-only change: publish the Vite build from client.
- API-only change: release the Express service from suvatsalya-backend.
- Content, sitemap, slug, or SEO-route change: release both applications together.

AFTER RELEASE
-------------

1. Open https://suvatsalya.in and test a public route and the admin login.
2. Verify an API request succeeds using the configured production API base URL.
3. Verify the static sitemap and the backend's `/api/seo/sitemap.xml` endpoint return XML.
4. Create or edit a test article/story in the admin panel and confirm its public
   slug URL, preview text, headings, and image render correctly.
5. Inspect one public page's title, description, canonical URL, and social image.
6. In Google Search Console, submit or refresh the static and dynamic sitemap URLs.

SECURITY
--------

- Keep .env files and all secrets out of Git.
- Do not use the local seed/admin account in production.
- Restrict CORS_ORIGIN to the production frontend origin and any explicitly
  approved preview origin.
- Store production MongoDB data separately from development data.
